## Why this note exists

The 2026-09-03 decision gave VG20 the Down syndrome joint role **conditionally**: it holds through the `us_03` ingestion refit, and VG22 takes it if and only if four criteria — fixed in advance, before the evidence existed — are met "on the refitted pool". _Failing any of the four, VG20 keeps the role and the failing criterion is the recorded reason._

That refit completed on 2026-09-08. Twenty-one models at `rep`, one Git revision, one raw-data fingerprint, one executable-code signature. **The criteria are therefore live, and none of them was scored by the refit itself.** Work started on 2026-09-09 and was paused after about half an hour; what follows is what was established, what is running order for the resumption, and what needs a study-owner decision before it can be scored at all.

## Criterion 3 cannot be scored: PSIS-LOO degenerated across the family

The criterion asks for a **paired** `loo_compare` of VG20 against VG22 at more than four standard errors, "with the Pareto diagnostics reported beside it". On the 2026-09-08 `rep` fits there are no usable Pareto diagnostics to report:

| model | outcome   | high-k or non-finite | share |
| ----- | --------- | -------------------: | ----: |
| VG22  | `y_u_obs` |          306 / 1,260 |   24% |
| VG22  | `y_joint` |          622 / 1,708 |   36% |
| VG21  | `y_joint` |        3,796 / 6,783 |   56% |
| VG23  | `y_joint` |        3,726 / 6,356 |   59% |

`loo_compare.py` marks each of these `[unusable]` in its own output — _"PSIS-LOO has degenerated here; do not compare this elpd with another model's"_ — and the only `az.compare()` tables the whole run produced were VG05 against VG07, the two models with no subject random effects. The decision note anticipated the exposure (it called the existing 205-nat advantage "two independent totals differenced by hand, with no standard error, resting on 477 of 1,409 spoken rows whose Pareto shape exceeds 0.7") but still set a criterion that needs the statistic.

### The substitute, and the one change made to enable it

`loo_compare.py`'s own message names the remedy: _"Leaving out one observation removes most of what identifies that child's effect, which is what leave-one-subject-out exists to measure instead."_ The right tool is **`scripts/kfold_loso.py`**, which the repository already calls a "gold-standard" comparison: it **refits per fold** rather than importance-weighting, so no Pareto diagnostic is involved at any point, and it emits a **paired** table (`kfold_loso_compare.csv`) with a standard error. That is what criterion 3 was reaching for.

VG22 was not in its supported set. Adding it was one line, for the reason the script's own comment gives: `build_model_re` dispatches on the definition's fields — through `subject_effects.resolve` — so the low-rank factor needs no separate builder, exactly as the child-slope (VG19) and correlated-intercept (VG20) structures did not. Both of the script's guards pass unchanged: every model in the set shares `n_trials = 810`, and every one uses the `product_marginal` spoken fallback the held-out likelihood implements. A held-out child's factor scores stay at their `Normal(0, 1)` prior during MCMC exactly as the other structures' subject REs do, because `subject_factor_z` is indexed by `subject_id` and only the likelihood drops the fold's rows.

The change is confined to `scripts/`, which the executable-code signature does not hash, so **no fit is restaled by it.**

**This is candidate evidence for a restatement, not a restatement made unilaterally.** Changing a criterion that was deliberately fixed before the evidence existed is a study-owner decision, and the discipline of #288 is the reason to say so rather than quietly substitute a statistic.

## Criterion 4 cannot be scored either — and it would not complain

`us_03` was ingested on 2026-09-06. It is now **284 rows of VG20's and of VG22's own 1,708-row training frames**. Criterion 4 says "the `us_03` scores repeated against the refitted models", and `scripts/predict_new_study.py` is the script that produced the original figures — a script whose first line is _"Score a model of record against a study it was never fitted to"_ and whose usage says the frame "must **not** be a study the model was fitted on".

**There is no guard in the code.** The only `raise` on that path is for an unknown model key. Running criterion 4 as literally written would return an optimistic in-sample number for both models, silently, and it would look like a result.

### The restatement this needs

The _question_ survives intact and is the right one: **can VG22 predict a child's second-visit comprehension from their first as well as VG20 can?** That is the dimension where VG20 was better by a distinguishable margin (6.36 nats, z +2.89, on the comprehension-only conditioning), and it is the task the child-effect correlation exists to perform. Only the vehicle is invalidated.

The recommended replacement keeps the question and drops `us_03`'s now-meaningless special status: **hold every child's later visits out of the likelihood, pool-wide, and score held-out second-visit comprehension under the visit-1-comprehension-only conditioning.** This is implementable as a holdout-unit option in `kfold_loso.py` rather than as new machinery, because `fold_fits.fit_holdout_fold` already takes an arbitrary boolean `holdout` column — _"those rows leave the likelihood but stay in `obs_id`"_ — so the unit is pure configuration. `wave_forward_score.py` already offers exactly this unit (`--holdout-unit later-waves`) but is **not** reusable here: it is hard-locked to cross-lag models and compares a model against itself with one field removed, not two different models.

Building it was deferred, because **a failure on any single criterion resolves the gate** and would make it unnecessary.

## What was measured before the pause

One number worth recording, because it changes the prior on criterion 2.

Criterion 2's quantity is `tau_subj_q_1`, the spoken child-slope scale. The disagreement that motivated the criterion was measured before the refit: **0.348 (sd 0.047) at rank 2 against 0.576 (sd 0.066) at rank 3, about 2.85 combined standard errors apart** ([`202608231420`](202608231420-vg22-factor-anchor-bimodality.md) §5, §7), against a threshold of about 1.5.

On the refitted pool, **rank 3 now reads `tau_subj_q_1` = 0.730 (sd 0.062)** — a large move from 0.576. That is the expected direction: `us_03` contributed 104 children with two visits, and repeat visits are what identify a child _rate_ at all. So the pre-refit expectation that criterion 2 fails is **no longer safe**, and the rank-2 fit genuinely has to be made rather than predicted. Two other things have also changed since that measurement: the anchor-order fix `(b0u, b0q, b1q, b1u)` is in the registered definition now (`definitions.py:421`), so a rank-2 fit is no longer the pre-fix one that needed a hightune; and the refitted `rho_uq` under VG22 is 0.340 [0.243, 0.434] against 0.311 [0.218, 0.400] before.

## Picking this up

Nothing usable was produced before the pause and nothing was left in a misleading state: the two `rep` fits were writing into `.staging/` and are promoted only atomically, so no model of record was touched; `kfold_loso.py` writes every CSV after its last fold, so it produced none; and the recovery replicate has its `truth.nc` but no `trace.nc`, which `--compare-only` skips by design. `D:\output\vocabulary-growth\.staging\VG22-20260909T0748*`, `kfold_tmp\` and `recovery\...-r01\` hold about 52 MB of abandoned partial output that a later run supersedes.

Run these from the repository root, with `PYTHONUTF8=1` and `MPLBACKEND=Agg`:

```bash
# Criterion 2 — the cheapest decisive answer, ~1 h 45 m.
uv run python scripts/fit_sensitivity.py vg22 rank-2 --config rep
# Optional, for "the rank re-selected on the refitted family" in full:
uv run python scripts/fit_sensitivity.py vg22 rank-1 --config rep

# Criterion 1 — ~5-6 h; resumable per replicate, and r01's truth.nc already exists.
uv run python scripts/fit_recovery.py vg22 --config rep --replicates 3
#   resume a partial run with, e.g.:  --replicate 2 --replicate 3
#   score whatever exists on disk with: --compare-only

# Criterion 3's candidate substitute — ~2 h (fold 0, both models, took 23 minutes).
uv run python scripts/kfold_loso.py --models VG20,VG22 --folds 5 --config test \
    --suffix vg20-vg22
```

**Order matters.** Criterion 2 is the cheapest and, on the evidence above, the most likely to decide the question outright; a failure there resolves the gate with VG20 keeping the role, and criteria 1, 3 and 4 then need not be run at all. Criterion 1 is the long pole and is the only one of the three that survives an interruption.

Criterion 4 needs the owner's restatement before anything can be built for it.
