# Statistical model review fixes

The 5 September 2026 code review found errors in GP centring, VG15's conditional composition likelihood, sensitivity comparisons and fit reuse checks. This change corrects the code and adds numerical regression tests. It does not supply new reporting-quality fits or revised empirical estimates.

- All six registered engines now construct their GP grid with the declared age-domain midpoint. Previously five engines allowed PyMC to choose the centre from observed and reporting ages together. Adding a reporting age could change the GP prior at existing observations. Tests build each engine twice with different query and plot grids and compare the observed-data log probability. A separate check compares the induced covariance for VG10. The existing synthetic grids for VG11 and VG12 had centres different from their declared domains, so their fixed-point log probabilities change and their stored references are updated.
- VG15 now conditions its four-cell Dirichlet-Multinomial on the produced total by retaining the three produced-cell Dirichlet parameters. If the four parameters are `conc * pi`, the retained concentration is `conc * (1 - pi_neither)`. Restoring the original `conc` after renormalising the three probabilities had made this a different distribution. An enumeration test compares the engine's actual parameters with the exact conditional four-cell distribution. The VG15 synthetic graph reference changes deliberately.
- Sensitivity comparisons validate both fits against the current registered definitions, including the actual override values, their own rebuilt analysis frames, executable-code signatures, sampling configuration, lifecycle state and recorded clean provenance. Rebuilding each variant's frame admits registered data restrictions while rejecting unrelated data changes. Both convergence gates affect the verdict. Unverified fits cannot receive a robustness verdict.
- Count summaries accept the existing unprefixed engine columns and VG15's outcome-prefixed columns. Signed counts are included. Coverage checks the quantities required by each engine and child-effect plan, even if both output directories omit them. Empty, non-finite, malformed or duplicate summary rows cannot silently shrink the comparison.
- Comparisons include the cross-lag, child-effect correlations, child-slope scales and correlations, and variance-partition parameters alongside trajectories. The detail table uses `base_estimate`, `var_estimate` and `estimate_kind`. Scalar diagnostic summaries contain means, so the table no longer mislabels them as medians. The criterion remains descriptive containment in the baseline's 89% interval. It does not prove general robustness or establish an equivalence margin.
- Fit manifests record an implementation signature, and reuse policies compare it with current code. The signature conservatively includes all executable Python code in the package and installed numerical-library versions. It ignores comments, documentation strings, whitespace and external documents. A change to reporting code can therefore invalidate a fit even if its likelihood is unchanged. This conservative scope avoids a dependency list that misses a new statistical helper. A missing signature is unverifiable and requires a refit; the validator does not backfill an untested claim about historical code.

Two documentation corrections clarify that integrating a shared scalar child intercept over repeated visits remains a one-dimensional integral with a product integrand, and that VG15's administration-level leave-one-out score includes its composition likelihoods. Its per-outcome scores exclude those terms.

Existing reporting-quality fits and sensitivity matrices must be regenerated before their numerical conclusions are treated as results of the corrected implementation. This change tests implementation and distributional identities; it does not measure the effect of the corrections on fitted vocabulary trajectories or association estimates.
