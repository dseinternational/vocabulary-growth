**1. The study-constraint rationale contradicts the retained data.**

In [common_bivariate_re.py](../src/vocab_growth/models/common_bivariate_re.py#L762), `build_model_re` constrains both sets of study offsets to sum to zero over every retained study. The accompanying comment says both outcomes are informed by every study. That statement is now false. PyMC applies the constraint over the chosen axis, so the axis membership determines which offsets must balance. See the [ZeroSumNormal documentation](https://www.pymc.io/projects/docs/en/latest/api/distributions/generated/pymc.ZeroSumNormal.html).

After rebuilding the database from this checkout, the default VG20 analysis frame has 1,708 rows from 15 studies. The relevant counts are:

| Study   | Understood observations | Spoken observations |
| ------- | ----------------------: | ------------------: |
| `us_03` |                     284 |                   0 |
| `nz_01` |                       0 |                 111 |

`us_03` contributes no spoken likelihood term, but its `delta_q` remains in the constraint. Consequently, the offsets of the 14 studies with speech data sum to `-delta_q[us_03]`, rather than zero. The population production-ratio curve therefore depends on an offset without direct speech evidence. The constraint can give that offset indirect information, so it is more precise to say "no direct speech evidence" than "its posterior equals its prior".

I checked all eight Down syndrome models using this builder. VG07, VG08, VG09, VG10, VG16, VG19, VG20 and VG22 all retain `us_03` without spoken observations. Under VG20's `paired_only` fallback treatment, `nz_01` also contributes no spoken likelihood, and neither its understood nor its spoken offset has direct outcome support.

This remains a valid probability model. Retaining the constraint over all studies and restricting it to studies with outcome evidence define different population references and different priors. The inaccurate comment alone does not establish which choice better serves the study. Correct the comment and state the intended reference first. If the intended reference includes only studies with evidence for that outcome, the joint engine offers an existing implementation through `informed_studies` and `informed_study_zero_sum` in [common_joint_modality.py](../src/vocab_growth/models/common_joint_modality.py#L1308). Such a constraint must use the rows that actually enter each likelihood after exclusions. For comprehension, those rows include spoken fallback observations when their mean depends on comprehension. A direct count of non-missing comprehension alone would therefore be insufficient.

Whichever reference is chosen, its regression check should include a study with comprehension only and a study with speech only, then repeat the check with `paired_only`. Assert which studies enter each constraint. Changing the constraint changes the prior and requires a documented statistical change and new fits. This review has not measured the resulting shift in any posterior estimate. The original draft recommended restricting the constraint too directly; the second review separates the confirmed comment error from that statistical choice.

**2. A reference age of zero means different things during fitting and prediction.**

[subject_effects.resolve](../src/vocab_growth/models/subject_effects.py#L280) uses `value or DEFAULT_SLOPE_REF_AGE_MONTHS`. Python treats `0.0` as false, so this replaces a requested reference age of birth with 36 months. In contrast, [the predictive offsets](../src/vocab_growth/models/common_bivariate.py#L1164), prior child checks and comparison code use an explicit `None` check and retain zero.

This definition passes `validate_model_definition`:

```python
definition = dataclasses.replace(VG19, subject_slope_ref_age_months=0.0)
```

The current functions then give:

| Quantity                             | During fitting | During prediction |
| ------------------------------------ | -------------: | ----------------: |
| Reference age, months                |             36 |                 0 |
| Slope multiplier at 24 months, years |             -1 |                 2 |
| Slope multiplier at 36 months, years |              0 |                 3 |

Both paths describe the child effect as an intercept plus a slope times years from the reference age. Their different reference ages therefore produce different child trajectories from the same parameter values. This affects customised definitions. Registered VG19 uses 36 months and does not trigger the mismatch.

The second review confirmed this in actual VG19 model builds. I evaluated the fitted comprehension shift with the child intercept set to zero and the child slope set to one, then compared it with the predictive multiplier on the model's own query grid. At a requested reference age of zero, the results were `[-1, 0]` during fitting and `[2, 3]` during prediction at 24 and 36 months. Requested reference ages of 24 and 36 months agreed between the two paths to numerical precision.

Use an explicit `None` check in the resolver and have fitting, prediction, prior checks and comparisons read one resolved reference age. Add a regression check that compares the actual fitted and predictive offsets at reference ages of zero and a positive value. Testing each path only at its default cannot catch this error.

**3. A one-study teaching example fails with division by zero.**

Both [the bivariate builder](../src/vocab_growth/models/common_bivariate_re.py#L766) and [the univariate hierarchical builder](../src/vocab_growth/models/common_univariate_re.py#L514) compute `sqrt(K / (K - 1))` without handling `K = 1`. I built VG20 and VG12 on the existing synthetic frame with every row assigned to one study. Both raised `ZeroDivisionError`.

A student who restricts the data to one study gets no explanation of the statistical issue. A study offset constrained to sum to zero must be zero when there is only one study. Either implement that case explicitly, as the joint engine does, or reject it before graph construction with an explanation and a suitable model alternative. This belongs with the shared study-offset work in finding 1.

**7. Give students one executable route through the real implementation.**

Start with a small synthetic dataset and VG01. Link each stage to the actual function it calls. Explain the model first in counts and probabilities, then show the corresponding arrays and PyMC variables. Introduce the logit as `log(p / (1-p))`, which allows an unrestricted real-valued predictor to represent a probability after applying the inverse transformation.

For the Beta-Binomial, state the quantities explicitly. With inventory size `N`, mean proportion `p` and concentration `kappa`, the mean count is `N*p` and the variance is `N*p*(1-p)*(N+kappa)/(1+kappa)`. These follow from substituting `alpha = p*kappa` and `beta = (1-p)*kappa` in the [PyMC distribution formulas](https://www.pymc.io/projects/docs/en/latest/api/distributions/generated/pymc.BetaBinomial.html). For `N > 1`, smaller concentration permits more count variation at the same mean. A numerical example should compare this with the Binomial before introducing an age-dependent concentration.

The next worked example can add `U ~ BetaBinomial(N, p_U, kappa_U)` and `S | U ~ BetaBinomial(U, q, kappa_S)`. These expressions use mathematical shorthand for the mean and concentration, not PyMC's positional argument order. The PyMC likelihood uses the keywords `n`, `alpha` and `beta`, with `alpha = p*kappa` and `beta = (1-p)*kappa`. Show that `q` is the expected fraction of understood words spoken, while `p_U*q` is the expected spoken fraction of the full inventory at fixed parameter values in this conditional model. Then introduce a study offset, a persistent child offset, correlated child offsets, and finally the signing composition. Each extension should answer a stated scientific question and show what changes in the formula.

Distinguish a curve at zero child and study offsets, an average over children, an expected trajectory for one new child, and a noisy future count. The inverse-logit transformation means these are not interchangeable. Also explain that flexible GP departures do not guarantee monotone vocabulary growth, even if the average trend rises.

Use the existing implementation in the tutorial so it stays aligned with the study. Include small exercises such as changing concentration, removing a parent count, restricting to one study and changing the child-slope reference age. These exercises would expose the current edge cases more directly than a tour of every configuration field.
