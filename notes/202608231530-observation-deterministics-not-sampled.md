# The observation-sized deterministics are no longer sampled

> [!NOTE]
> Drafted by an LLM-based AI tool (Claude Code/Fable 5).

> [!IMPORTANT]
> Implementation record, 2026-08-23, for lever №1 of [202608231410](202608231410-td-geometry-remaining-levers.md) §2 — the first of the two changes the study owner adopted there, and the settlement of [202608050900](202608050900-td-hierarchical-geometry.md) §11 open item 3. Built on a worktree while the VG22 rank family was refitting from `0a4495a`, so the main checkout stayed clean for those fits' provenance. §3 and §4 are measured on `dev` and `test` fits made for the purpose; §3 also records a LOO subtlety the change exposed rather than caused.

## 1. What changed

The engines' shared `sample` stage now gives `pm.sample` a `var_names` list — every free random variable plus every deterministic that is not indexed by an observation dimension or the concatenated `all_id` grid (`fit_artifacts.sampled_variable_names`, the same dimension rule `plan_trace_persistence` already applied to a `compact` write). PyMC forwards it to `nutpie.compile_pymc_model`, and nutpie's expand function then never evaluates the excluded variables. For VG10 that is fifteen of them: `f_u_obs`, `p_u_obs`, `h_obs`, `q_obs`, `f_s_obs`, `p_s_obs`, `kappa_u_obs`, `kappa_s_obs`, `z_obs`, `f_u_all`, `h_all`, `g_u`, `g_q`, `g_unit_u`, `g_unit_q`. The model graph is untouched — those deterministics still exist in it — and so is the `logp` the sampler follows, so the draws are identical (§3).

What the trace and manifest record: `trace.posterior.attrs["not_sampled_deterministics"]` holds the excluded names as a JSON list (a string, because netCDF attribute support for string arrays differs between backends), and `save_trace` copies it into `fit_manifest.json` under `artefacts.trace.not_sampled`. A trace without the attribute predates the change and stored everything; a reader finding no `f_obs` can therefore tell "never sampled" from "dropped by tier" from "truncated".

What reads them now: `vocab_growth.posterior_recompute.with_deterministics(posterior, model, names)` returns a posterior carrying the requested names, computing the absent ones with `pm.compute_deterministics` from the stored free parameters on a rebuilt model graph and leaving present ones alone — so the same call serves old and new fits, and computes nothing when nothing is missing. `common_bivariate_re.rebuild_model_context(definition, output_dir=...)` builds that graph through the engine's own data preparation, so observation order and every data rule are those of the fit; callers check the fit against the registered definition and the current source-data hash first (`fit_artifacts.validate_fit_output`), because recomputing on a different graph or different rows would be silently wrong.

## 2. What the consumer audit found

Nothing in the fit pipeline read them. The three extractors (`extract_model_samples` in the univariate, bivariate and trivariate engines) copied the observation-level posterior into their sample structs at `n_obs × n_samples` each — a second full copy on top of the trace — and no plot, summary or comparison read those fields; they are removed from the structs, with a test pinning their absence. The bivariate and trivariate `diagnostics` named `kappa_*_obs` for the trace plot, but `capped_plot_var_names` counts a variable's non-sample elements against ArviZ's 40-subplot cap, so an observation-sized variable has never rendered on any real dataset; the names are gone and the trace plot is unchanged (byte-identical in §3).

Two scripts read them post hoc. `scripts/kfold_loso.py` fits its own folds and reads `p_u_obs`/`p_s_obs`/`q_obs`/`kappa_*_obs` at held-out rows across every draw, so it asks `sample(context, store_observation_deterministics=True)` — recomputing would cost the same memory and a second pass. `scripts/loso_compare.py` reads `f_u_obs`, `h_obs`, `kappa_u_obs`, `kappa_s_obs` from the VG07–VG09 traces on thinned draws and is in the standard comparison phase, so it takes the recompute path: thin first, then `with_deterministics` on the thinned posterior, with the rebuild guarded by fit validation. `scripts/regenerate_plots.py` required a full trace only because the extractor read `f_obs`/`p_obs`; it keeps the requirement conservatively, with the comment corrected. Parameter-recovery scoring excludes observation-dimensioned targets by rule and is unaffected; `require_full_trace` still means what its remaining callers need — the stored `log_likelihood` and the scaled random effects — and its docstring now says so.

## 3. Equivalence, measured

**The regression tests** build the real VG07 graph on synthetic data and sample it twice with nutpie (12 draws, same seed), storing everything once and not the second time: the free-parameter draws are bit-identical; the recomputed `f_u_obs`/`h_obs`/`kappa_*_obs` match the stored ones to 1e-10 relative; the trace attribute and the manifest record round-trip; and — the case a real fit caught that the first test did not — recomputation on a _thinned_ posterior works, because `pm.compute_deterministics` relabels the draw axis 0..n-1 and the helper now carries the input's own labels over before its exact-join merge.

**VG10 at `dev`, old code against new**, same seed, to two scratch roots. Identical file sets (175 files). Posterior: 75 variables before, 60 after; the 15 missing are exactly the excluded list; of the 60 in common, **48 bit-identical — every free parameter, every scaled effect, the sample statistics — and 12 within 1e-11 relative** (the grid deterministics; worst `f_u_plot` at 9.9e-12). The stored `log_likelihood` is bit-identical: 0 of 1,428,000 and 0 of 987,000 elements differ. Of the reporting artefacts, 90 are byte-identical (every PNG figure, the trace plot among them) and the rest differ only as follows: 18 CSVs by at most 2.6e-13 relative (summaries, trajectories, learning rates, production ratios — numerically the same tables printed from floats that differ in the last ulp), SVGs by their embedded creation timestamps, and `loo_summary.csv` — see below.

**VG07 at `dev`, recompute on a real fit**: with the after-fit validated against the registry and the current data hash, the model rebuilt, and `f_u_obs`, `h_obs`, `kappa_u_obs`, `kappa_s_obs` recomputed on every 36th draw, the maximum relative differences against the before-fit's stored values are 1.0e-13, 4.2e-14, 0 and 0. `scripts/loso_compare.py` run end to end on each root: the **marginal** LOSO — the path that consumes those four — reports elpd −13077.660035511017 from both, `p_loo` to 1e-14; the conditional LOSO, which reads the stored log-likelihood, differs in the fourth significant figure for the reason below.

**The one non-rounding difference, and why it is not this change.** `loo_summary.csv` moved: VG10's spoken elpd −6354.83 → −6354.61 (SE 78.6), `p_loo` 590.98 → 590.76, and the Pareto-k bands by 8–10 of 1,416 observations. The log-likelihood it is computed from is bit-identical, so the difference is in `az.loo`, and it is `reff`: ArviZ's default relative efficiency is the mean ESS over **every variable in the posterior group** ÷ draws (`arviz_stats.loo.loo_helper._get_r_eff`, "this mean is over all data variables"). Before, that average ran over 32,373 elements dominated by the observation-level deterministics and came to 0.5613; after, over 7,818 elements, 0.5540. A 1.3% change in `reff` moves the PSIS tail length by one sample at 1,000 draws, and at `dev` enough observations sit near the k thresholds for ~10 to flip. Over the sampled parameters alone the same quantity is 0.9047 — `reff` in this project had been an accident of what happened to be stored, not a property of the sampler. The study owner's decision on seeing this was to pin it (§7).

The precise statement, then: **identical draws; derived quantities to floating-point rounding; LOO identical once `reff` is pinned (§7), and to the `reff` convention where it is not.** "Byte-identical reporting output" — the compact tier's claim, which held because it filtered the same in-memory trace at write time — is not the right words here, because nutpie compiles a different expand function when fewer outputs are requested and PyTensor's loop fusion then rounds the last ulp of the grid deterministics differently (4.4e-16 absolute on the VG07 test graph, 9.9e-12 relative at worst on VG10 `dev`). Nothing read at printed precision changes.

## 4. Memory, measured

Stored-trace side, both at `dev` (2 × 500 draws): VG10's `trace.nc` 306.6 MB → 110.1 MB and its posterior group 259.0 MB → 62.6 MB in memory (a factor of 4.1 on what the sampler accumulates); VG07's `trace.nc` 281.9 MB → 85.5 MB. What remains is the free parameters, the scaled study and subject effects (subject-sized, kept for the name-preserving contract every reader relies on), the plot/query-grid deterministics, `log_likelihood` and `posterior_predictive`.

In-fit peak, VG10 at `test` (4 × 4,000 iterations, 8,000 stored draws), old code against new, process RSS sampled every 10 s through the whole fit: **5.45 GB → 3.33 GB peak** (private bytes 7.21 → 4.26 GB), both peaks at the end of sampling as nutpie's buffers are converted to the in-memory trace. `trace.nc` 2,450 MB → 879 MB; posterior group 2,072 MB → 500 MB. Wall time 9 m 30 s → 9 m 06 s (sampling 5 m 58 s → 5 m 45 s, diagnostics 53 s → 37 s). The in-fit saving is smaller than the stored-bytes factor because what remains — the model and its compiled functions, the data, `log_likelihood` and `posterior_predictive` at observation size, the plotting stages — does not shrink; the share that does shrink is the one that grows with `n_obs × draws`.

What this implies at `rep`: [202608050900](202608050900-td-hierarchical-geometry.md) §10's arithmetic — memory dominated by `n_obs × draws` through these variables — is what the change removes, and the typically-developing pools are where that term is largest (VG12: 7,052 observations, 15 such variables, 36,000 draws — some 30 GB in the posterior group alone before any copy). The VG22 rank-family `rep` fits running on the old code during this work sat at 16–17 GB in their post-sampling stages for a DS bivariate model of ~1,400 rows, and VG13's `rep` fit was measured near 178 GB on 2026-08-22. The factors above are the honest extrapolation basis; the first `rep` fit on the new code should be measured rather than predicted, and the first TD one is the measurement that matters.

## 5. Consequences for the persistence tiers and the docs

`compact` now has only the duplicated scaled random effects left to drop — the observation-sized half of its job is done at the source — and `minimal`'s trade (`log_likelihood`, `posterior_predictive`) is unchanged, so the tier vocabulary survives. The 9.8 GB → 3.2 GB VG10 measurement in [202608081445](202608081445-trace-persistence-tiers.md) dates from when the variables were still stored; that note is left as the record it is. `CLAUDE.md`/`AGENTS.md`/`.github/copilot-instructions.md` (`--trace-persistence`) and the full-refit runbook carry the dated qualification.

## 6. What this does not do

It does not touch VG17's own `pm.sample` call (the exploratory sign-group module, which writes no manifest), and it does not drop the scaled random effects at sampling time — `delta_subj_u`/`delta_subj_q` and the study `delta_*` keep the name-preserving contract every summary, comparator and the recovery scorer read them by. Those are subject- and study-sized, an order of magnitude smaller than the observation-sized variables at the TD pools' 1.2 observations per child, and excluding them is a separate decision with readers to rewire.

## 7. Decision: `reff` is pinned to the sampled parameters

Taken by the study owner on 2026-08-23, on seeing §3, and implemented the same day. `vocab_growth.loo_reff.sampled_parameter_reff` computes exactly ArviZ's quantity — mean ESS (`method="mean"`) over every element of the named variables, divided by the number of draws, 1.0 for a single chain — restricted to the model's free random variables, and every `az.loo` in the project goes through it: the in-fit diagnostics (names from `model.free_RVs`; the value is printed and lands in a new `reff` column of `loo_summary.csv`), `scripts/loso_compare.py` (names from the trace's record or from the rebuilt model it already has) and `scripts/loo_compare.py` (names from the record). `az.compare` is fed the precomputed `ELPDData` rather than traces in both scripts, because handed traces it recomputes LOO with its own default. The `sample` stage now also writes the free-RV names into the trace (`fit_artifacts.SAMPLED_PARAMETERS_ATTR`, copied to the manifest as `artefacts.trace.sampled_parameters`), so a stored fit can be read the same way without the model.

What it buys, measured: `loso_compare.py` on the before- and after-fits of VG07 at `dev` — one storing the observation-level posterior, one not — now reports identical conditional LOSO to every printed digit (elpd −12696.654161531327, `p_loo` 75.23834499724661; `reff` 0.8909 for both), where the default convention had them apart in the fourth figure. The marginal LOSO, already identical, stays so (its `reff` is 1.2096 on the thinned posterior, above one as thinning allows). For VG10 at `dev` the pinned value is 0.9047 against 0.5613 under the default, so absolute LOO numbers move once for every model and the Pareto-k bands with them — a one-time step, in exchange for a convention that no storage policy can shift.

What it does not yet cover: a trace written before the record existed can be pinned only when the reader can name the parameters. `loso_compare.py` always can (it rebuilds VG07–VG09's graphs); `loo_compare.py` spans every engine and does not rebuild, so for pre-2026-08-23 traces it falls back to ArviZ's default with a one-line notice per model and an empty `reff` column, and a comparison that mixes the two conventions says so in its output. That gap closes as the models of record are refitted, which the full refit will do.
